# Dev Setup — SDLC Phase 4 開發前準備

依 `../sdlc-orchestrator/SDLC_主流程版_IAO.md` 步驟 18-20。**Lead-direct，版控步驟只能列清單，不自動執行。**

## 提問規則（本階段所有對使用者的提問一體適用）
需要使用者拍板的事（排程優先序、分支策略選擇等）**MUST 選項化**：每題附 2-4 個具體選項（建議的放第一個並標「建議」），使用者勾選或回編號即可；自由補充永遠允許。一次一批 ≤5 題；後面的題目依賴前面答案時分批問。禁止開放式問答轟炸。

## 觸發條件
- 設計文件已確認（來自 system-design 或使用者直接提供）
- 不適用：設計還沒做 → 先回 system-design

## 完成條件（Phase Exit Criteria）
3 個步驟的 Output 都產出，且通過本階段專屬檢查（完整條目 → `references/phase-exit-criteria.md`）：
1. 可運行的專案骨架
2. 版控就緒（只列清單，不自動執行）
3. 開發排程

## 持久化
版控清單、開發排程 MUST 寫成 `docs/dev-setup.md`；專案尚無 `docs/` 資料夾就直接建立，不用先問使用者。專案骨架本身就是實際建立的檔案，天然已持久化，不用另外記錄。

## 流程

### 步驟 18：建立專案骨架與開發環境
- Action：建 repo、專案結構、裝環境
- 誰做：Lead 依技術選型執行；若在既有模組/專案內開發，骨架通常已存在，此步驟跳過
- Output：可運行的專案骨架

### 步驟 19：設定版控與分支策略
- Action：設定 Git、分支規則
- 誰做：**Lead 只列清單交給使用者執行**——NEVER 自動建 branch / push，本步驟不可自動化（版控安全紅線，不論哪個專案都適用）
- Output：版控就緒（清單形式：建議分支名稱、命名規則、目標 MR）

### 步驟 20：排定開發排程
- Action：排序、估時、排 timeline
- 誰做：Lead + 使用者
- Output：開發排程（依任務清單粗估，不用精確到工時）

## 停止條件
- 使用者要求 Lead 直接建分支/push → 拒絕，這是版控安全紅線，改列清單交給使用者自己做
- 發現前面階段（`system-design`）的產出有問題（例如設計文件缺任務清單、範圍不清）→ 明確告知使用者要回 `system-design` 重新確認，不要在已知有問題的情況下把骨架/排程做完

## 下一步
3 個 Output 都有了 → 提示使用者可以接著用 `implementation-handoff` 確認開發實作前置條件。**不自動呼叫**，只是提醒。
