# System Design — Phase Exit Criteria 詳細清單

每個步驟的具體檢查項，全部確認才算 Phase 3 完成、可以進入 Phase 4。

## 步驟 11 系統架構設計
- 分層/服務邊界清楚畫出
- 技術選型有明確理由（不是「因為習慣」）
- 標明是否新增外部資源/服務
- 標明影響哪些既有模組

## 步驟 12 資料庫設計
- ER 圖涵蓋所有新增/異動的資料表
- 標明使用哪個資料庫/datasource（若專案有多重資料庫架構）
- 有無跨資料庫一致性需求
- Migration 計畫（資料量、downtime、回滾方案）

## 步驟 13 API 設計
- 端點清單 + method + 請求/回應格式
- 錯誤處理格式一致
- 是否需要向下相容（既有 client 呼叫）

## 步驟 14 前端元件規劃（若涉及前端）
- 元件清單標明可重用範圍
- 頁面組成藍圖涵蓋所有使用情境

## 步驟 15 模組拆分
- 標明涉及哪些模組/套件邊界
- 模組邊界清楚，無循環依賴

## 步驟 16 拆分任務/開票
- 每張票的驗收標準可獨立驗證
- 標明跨模組的票，避免漏派
- 每張票已指派票號（Phase 5 的 handoff-log 以票號記完工狀態，沒票號對不上帳）

## 步驟 17 設計文件
- 彙整以上所有產出成單一文件
- 標記設定/機敏資訊管理系統異動（若有）
- 標記跨環境部署影響（若有多環境部署）

## 與既有機制的關係
本階段是新內容，不涉及分工問題；不變性（invariants）、邊界條件、回滾方案、模組邊界等判準已內建在步驟 11-17 各自的檢查項裡，不需要額外套用其他審查框架。
