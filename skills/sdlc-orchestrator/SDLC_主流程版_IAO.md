# SDLC 專案開發流程 · 主流程版(前後端分開)
---

## 一、需求發想階段

### 1. 蒐集原始需求
- **Input**：客戶 / 主管 / 使用者的零散訴求
- **Action**：訪談、記錄、彙整
- **Output**：原始需求清單

### 2. 釐清問題本質與商業目標
- **Input**：原始需求清單
- **Action**：追問「為什麼」,挖出真正要解決的問題
- **Output**：問題陳述 + 商業目標

### 3. 定義目標使用者與使用情境
- **Input**：問題陳述 + 商業目標
- **Action**：描繪誰用、在什麼情境用
- **Output**：使用者與情境描述

### 4. 發想解決方案
- **Input**：問題陳述 + 使用情境
- **Action**：擴散發想多個解法(不收斂)
- **Output**：候選方案清單

### 5. 初步可行性評估
- **Input**：候選方案清單
- **Action**：從技術 / 時間 / 成本評估
- **Output**：可行方案

---

## 二、需求分析階段

### 6. 收斂功能清單
- **Input**：可行方案
- **Action**：拆成具體功能項目
- **Output**：功能清單

### 7. 劃定範圍
- **Input**：功能清單
- **Action**：決定這版做 / 不做
- **Output**：範圍界定

### 8. 功能優先排序
- **Input**：in-scope 功能清單
- **Action**：依重要性 / 急迫性排序
- **Output**：排序後功能清單

### 9. 撰寫需求規格文件
- **Input**：排序後功能清單 + 範圍
- **Action**：寫成正式規格(每個功能的細節、規則)
- **Output**：需求規格書

### 10. 盤點依賴、風險與限制
- **Input**：需求規格書
- **Action**：找技術依賴、風險、限制
- **Output**：依賴 / 風險 / 限制清單

---

## 三、設計階段

### 11. 系統架構設計
- **Input**：需求規格書 + 風險清單
- **Action**：決定分層、服務、技術棧
- **Output**：系統架構圖 + 技術選型

### 12. 資料庫設計
- **Input**：需求規格書 + 系統架構
- **Action**：設計實體關係與資料表
- **Output**：ER 圖 / DB schema

### 13. API 設計
- **Input**：系統架構 + DB schema
- **Action**：定義端點、請求 / 回應格式
- **Output**：API 規格

### 14. 前端元件規劃
- **Input**：需求規格 + 使用情境 + API 規格
- **Action**：識別要哪些可重用元件、每個頁面由哪些元件組成
- **Output**：元件清單 + 頁面組成藍圖

### 15. 模組拆分
- **Input**：系統架構 + API 規格 + 元件清單
- **Action**：把系統切成模組,定義邊界
- **Output**：模組劃分

### 16. 拆分任務 / 開票
- **Input**：模組劃分 + API 規格 + 元件清單
- **Action**：把設計切成可執行的開發任務
- **Output**：任務清單(tickets)

### 17. 產出設計文件
- **Input**：以上所有設計產出
- **Action**：彙整成完整設計文件
- **Output**：設計文件

---

## 四、開發前準備

### 18. 建立專案骨架與開發環境
- **Input**：技術選型 + 設計文件
- **Action**：建 repo、專案結構、裝環境
- **Output**：可運行的專案骨架

### 19. 設定版本控制與分支策略
- **Input**：專案骨架
- **Action**：設定 Git、分支規則
- **Output**：版控就緒

### 20. 排定開發排程
- **Input**：任務清單
- **Action**：排序、估時、排 timeline
- **Output**：開發排程

---

## 五、開發實作階段

### 21. 資料庫建置
- **Input**：DB schema
- **Action**：建立資料庫、資料表
- **Output**：可用的資料庫

### 22. 後端 API 開發
- **Input**：API 規格 + 資料庫
- **Action**：實作後端邏輯與 API
- **Output**：可運行的後端 API

### 23. 前端元件開發
- **Input**：元件清單 + 元件設計
- **Action**：實作 前端 元件(可跨頁重用,先用假資料)
- **Output**：完成的前端元件

### 24. 前端頁面組裝與串接
- **Input**：頁面組成藍圖 + 元件 + 後端 API
- **Action**：把元件組裝成頁面,接上真實 API
- **Output**：可用的前端頁面

---

## 六、測試階段

### 25. 單元測試
- **Input**：各模組 / 元件程式碼
- **Action**：針對單一函式 / 模組 / 元件寫測試
- **Output**：單元測試結果

### 26. 整合測試
- **Input**：整合後的模組
- **Action**：測模組間、前後端互動
- **Output**：整合測試結果

### 27. 功能 / 驗收測試
- **Input**：完整功能 + 需求規格
- **Action**：對照規格驗收
- **Output**：驗收結果

### 28. Bug 修正與回歸測試
- **Input**：測試發現的 bug
- **Action**：修 bug、重測確認沒弄壞其他功能
- **Output**：修正後穩定的版本

---

## 七、部署階段

### 29. 部署前檢查
- **Input**：穩定版本
- **Action**：檢查環境、設定、資料就緒
- **Output**：部署檢查清單(通過)

### 30. 部署到測試環境(staging)
- **Input**：通過檢查的版本
- **Action**：部署到 staging
- **Output**：staging 運行

### 31. 部署到正式環境(production)
- **Input**：staging 驗證通過的版本
- **Action**：部署到 production
- **Output**：production 上線

### 32. 上線後煙霧測試
- **Input**：production 環境
- **Action**：快速測核心功能是否活著
- **Output**：煙霧測試結果(綠燈 / 退版)

---

## 八、維運階段

### 33. 系統監控與日誌
- **Input**：production 環境
- **Action**：建立監控、收集日誌
- **Output**：監控儀表板 / 日誌

### 34. 收集回饋與問題
- **Input**：使用者行為 + 回報
- **Action**：蒐集、彙整
- **Output**：回饋 / 問題清單

### 35. 修正與優化
- **Input**：回饋 / 問題清單
- **Action**：修正、優化(有新需求時回到流程重跑)
- **Output**：改善後的系統
